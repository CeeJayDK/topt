# TOPT_Blur.fx — the research blur effect

Generated by `python -m scripts.make_effect`. Copy it into your ReShade
`Shaders` folder (needs `ReShade.fxh`).

* `TOPT_BLUR_SIZE` (preprocessor): blur sigma in pixels at 1080p, integer
  1..200 (default 16). 1 is a single pass for sigma 0.7..1.3 (set with the
  fine-tune slider). It scales with the resolution and picks the size class
  (downsample factor) at compile time.
* `Size fine-tune` slider: x0.7..x1.33 at runtime; the blur stops growing
  at the edges of its size class.
* `TOPT_BLUR_FORMAT`: RGB10A2 (default) or R11G11B10F for HDR (> 1) values.
* `TOPT_BLUR_LUMA`: 1 blurs brightness only (Rec. 709 luma of the stored
  values) in one-channel buffers (`TOPT_BLUR_LUMA_FORMAT` R16F, or R8), and the
  composite replaces each pixel's luma with the blurred luma, keeping its colour
  detail. For sharpening / local contrast / exposure style consumers.
  Ignores `TOPT_BLUR_BLEND` (the mix needs the pixel's own luma).
* `TOPT_BLUR_DITHER` (default 1): dither of the output against banding, ±1
  step of the screen format (`BUFFER_COLOR_BIT_DEPTH`). Independent noise per
  colour channel: a one-step change of one channel is a third of a step in
  brightness and hard to see as colour, so the output gets ~3 x as many
  brightness levels. Methods: 0 off; 1 blue noise, triangular (one read of a
  64 × 64 four-channel blue-noise texture, each value remapped to triangular
  by the inverse distribution, which keeps the spectrum blue); 2 blue noise,
  triangular as the sum of two reads; 3 blue noise, rectangular (±0.5 step);
  4 blue noise, triangular, the same in all channels; 5 IGN, triangular (no
  texture); 6 Bayer 8 × 8 ordered (no texture). One value added to green and subtracted
  from red and blue (-,+,-), as small brightness steps as three channels for
  the price of one: 7 plus dither, 5 levels (frac(dot(pos, (1/5, 2/5)) + c));
  8 SweetFX 1 ordered dither (frac(dot(pos, (1/16, 10/36)) + 1/4), 144 levels,
  (+,-,+)); 9 IGN, rectangular; 10 blue noise, rectangular (one texture
  channel); 11 R2 ordered dither (frac(dot(pos, (0.7548777, 0.5698403)))) and
  12 a 32-level lattice ((8 x + 13 y) / 32), the best of
  `scripts/dither_lattice.py` (`results/dither_lattice.md`); both as t -
  round(t), with the add-round (1.5 * 2^23, `precise`) on NVIDIA, where round
  and frac are slow, frac elsewhere. Also in Movie Night's bars.
* `TOPT_DITHER_TEST` 1: the effect shows a grey gradient (0.25 at the left to
  0.75 at the right: bands of 15 px at 1080p without dither) in 13 stripes, methods 0-12 from the
  top, to compare them.
* `TOPT_BLUR_NOISE`: noise for the frosted glass: 0 the blue-noise texture,
  1 IGN.
* Both effects explain their preprocessor definitions (with the current
  values) under "Help: preprocessor definitions" in the ReShade UI.
* `TOPT_BLUR_FROST`: 1 scatters the final read inside a disk (frosted glass).
  `TOPT_BLUR_FROST_SHARE` (default 30) makes the blur passes that many % narrower
  (they pick their size class for the narrower blur), and the disk radius is set
  to give the full width back: a disk of radius R adds (R / 2)² to the variance,
  so R = 2 √(σ² − σ_blur²) (σ 32, share 30: R ≈ 46 px). The `Extra frosted glass
  radius` slider adds to it. Raise the share until the grain shows. The model
  expects savings only where a narrower blur picks a cheaper class: the cost is
  nearly flat above σ ~15 and rises below it.
* `TOPT_BLUR_BLEND`: 1 blends with the screen through the pass blend state
  (SrcBlend = SRCALPHA) instead of reading the backbuffer and lerping in the
  shader. Same result (both blend the stored, non-sRGB values); the composite
  saves one fetch and a few ALU when Strength < 1 or in the live-uniforms
  mode (with Strength 1 baked in, the compiler already drops the read).
* `TOPT_GPU`: the size classes are chosen per GPU family from `__VENDOR__` /
  `__DEVICE__` (the cost model calibrated on that architecture's TexBench
  report, see the main README); unknown GPUs get the least-regret choice over
  all profiles (`TOPT_GPU` 0). Set `TOPT_GPU` to force a table, e.g. to time
  them against each other.
* To use the blur in your own effect: run the `Down1` [`Down2`] `Blur` [`Up`]
  passes and call `TOPT_BlurResolve(uv)` in your final pass.

Passes: one wide downsample (x8 then the rest above sigma ~27), a runtime-width
Gaussian at low resolution (one 2D pass, or H + V passes where that is clearly
cheaper), and the upsample fused into the composite: a pinwheel, or in the "e"
classes one bilinear read (medium quality once the low-res Gaussian is wide
enough, sl >= 2.0-2.6, so each "e" class covers the upper part of its factor's
range; in-between factors x6, x12, x24 and x48 fill the gaps). Size 1 is a single pass in the composite: a centre texel plus a 4-fold
pinwheel of 2x2 texel blocks, each reproducing its block's Gaussian weights
exactly with one bilinear fetch (9, 13 or 17 fetches as sigma grows). Modelled
cost on a GTX 1660 at 1080p (its table), over a plain composite pass:

| sigma (1080p) | method | us |
|---|---|---:|
| 0.7–0.9 / –1.1 / –1.3 | single pass, 9 / 13 / 17 fetches | 77 / 126 / 175 |
| 2 | x2, 2D | 126 |
| 3 | x2, separable | 157 |
| 4 / 5–6 | x4 (+x2 up pass), 2D / separable | 109 / 111 |
| 7–12 | x4, separable | 95–104 |
| 13–14 | x8, separable | 74–75 |
| 15–18 | x6 "e", separable | 65 |
| 19–27 | x8 "e", separable | 61–62 |
| 28 / 29–35 | x8 + x2 / x4 + x3 "e", separable | 76 / 65–66 |
| 36–53 | x8 + x2 "e", separable | 61–63 |
| 54–81 | x8 + x3 "e", separable | 62–63 |
| 82–83 / 84–108 | x8 + x4, separable / "e" | 79 / 64–65 |
| 109–162 | x8 + x6 "e", separable | 68–69 |
| 163–166 / 167–200 | x8 + x8, separable / "e" | 89–90 / 75 |

Splitting x16 and more into x8 first matters on this card: one x16 pass writes
a 120 x 67 target with 144 reads per pixel, too few pixels to fill the GPU
(TexBench's under-filled pass test: 64 reads into 120 x 67 take 0.16 ms).

(Cost model calibrated against TexBench, see the README.)

# MovieNight.fx — blurred letterbox bars

CeeJay.dk's Movie Night (MIT) on the topt blur: the black bars of letterboxed
(or pillarboxed) video show a soft, blurred continuation of the picture. Each
bar pixel shows the picture point CeeJay's mapping gives it (the picture zoomed
towards the centre by the bars' share of the screen). Each bar zooms only
across itself (top / bottom vertically, left / right horizontally) so the glow
lines up with the picture next to it; the corners zoom both ways, with a
smooth change over twice the side bar's width.

* `MOVIENIGHT_BLUR_SIZE`: blur sigma in pixels at 1080p (default 32, at least 2
  px at the running resolution).
* Bars: Manual (Top / Bottom / Left / Right, in pixels) or Detected (below);
  Opacity; Zoom shrinks the bar geometry (for testing).
* Bar content: pure black shows the glow. Feather (8-bit levels, default 0 =
  only pure black): bar pixels from 0 up to this level get the glow too, less
  the brighter they are (opacity = level / Feather), so a subtitle shadow set
  to near black in the player lies over the glow; brighter (subtitles) covers
  it. Edge feather (default 16) does the same next to the picture, where
  compression leaves the bars almost black (edge bleed), changing to Feather
  over Edge feather width (16 px). Fill the whole bars (test): ignore the
  content, e.g. to see side bars on full-screen video.
* Bar detection: the technique "Movie Night: detect bars" (`timeout` =
  `MOVIENIGHT_DETECT_MS`, default 1000 ms: switch it on, it switches itself
  off; it must come before MovieNight) writes the bars to a 2 x 1 texture that
  MovieNight reads with Bars = Detected. One pixel runs a binary search per
  bar over the lines from the screen edge inward; a probe reads 16 points at
  the corners between 2 x 2 pixels along two lines (any light in 4 pixels
  per read). Top first (first probe at the 2.35:1 bar), bottom from the top's
  result mirrored, then left / right (first probe at the 4:3 bar) on the rows
  between them; each search first tests the two outermost lines, so a side
  without a bar costs one probe (~200-400 reads in all). It keeps the
  smallest bars over the frames it runs (a dark scene can hide the
  picture's edge) and skips almost black frames. Light is anything above 0,
  so edge bleed counts as picture.
* `MOVIENIGHT_SOFT_GLOW`: the glow gets wider towards the outer edge of the
  bars (smoothstep from the picture edge to the screen edge, scaled by Soft
  glow), in the final pass, no extra passes. 1: a ring of 8 bilinear reads
  of the blur's last level, radius up to 2.5 sigma (it takes over from the
  smooth upsample once the radius is sigma / 2). 2: the
  read moved by the same radius in a direction from the blue noise zoomed by
  Frost grain (default 8 px, bilinear), so it glides from pixel to pixel like
  frosted glass; one noise read. Both about double the sigma at the screen
  edge, and widen the strips the blur
  passes draw by their radius. Estimated cost: `results/movienight_cost.md`
  (frost about +15-25 % of the technique, the ring +35-60 %, more on Intel).
* The blur works on the picture only: its passes draw only the strips of the
  picture the bars show plus the blur's reach, cut to the picture, and every
  read (screen and low-res levels) is clamped to the pixel / texel centres
  inside the picture. Nothing is drawn in the bars except the final pass, the
  cost follows the bar area, and the bars do not darken the glow. The low-res
  buffers keep their full-screen size (texture sizes are fixed at compile
  time, the bars are UI settings); they are small (x16 at 4K: 240 × 135).

# Hardware timing effects

Generated by `python -m scripts.make_fx` (regenerate after new search results).
Copy the `.fx` files into your ReShade `Shaders` folder.

| file | purpose |
|---|---|
| `TOPT_Bench_Micro.fx` | calibrate the cost model |
| `TOPT_Bench_Blur.fx` | optimizer winners and classic methods (blur fused into the composite pass) |
| `TOPT_Bench_CS.fx` | compute tile blur + the mandatory composite pixel shader (D3D11+/GL/Vulkan) |
| `TOPT_Bench_Order.fx` | identical taps in different fetch orders (texture-cache locality) |
| `TOPT_Bench_Noise.fx` | noise sources for scatter / frosted-glass passes: IGN, R2, hash, a hard-coded table, blue-noise textures 4²–512² in RG8, R8, RGBA8 and R8 with two packed 4-bit values |
| `TOPT_Bench_Layout.fx` | full-res separable blurs: H→V, V→H, H written transposed, and H/V split over two render targets |
| `TOPT_Bench_Quad.fx` | 2 × 2 quads sharing their reads through `ddx_fine` / `ddy_fine` vs the exact pinwheel (sigma 0.8, 1.0, 1.2) |

The noise benchmark and `TOPT_BLUR_FROST` need the blue-noise textures: copy
`fx/Textures/*.png` into ReShade's `Textures` folder.

Every technique ends in a composite pass that reads the backbuffer and writes
the screen (`TOPT_Strength` blends; 1 = full blur). The cost of a blur is its
GPU time minus `TOPT_M_Composite`.

`TOPT_Bench_CS.fx` also comes as a ready-to-run package for the Test Host of
[sopt](https://github.com/CeeJayDK/sopt): `python -m scripts.cs_package --testhost
Test-Host-<version>.zip --shaders <folder with ReShade.fxh>` writes
`dist/TOPT-CS-Bench.zip` (the Test Host, `TOPT-CS-Bench.bat`, the same shaders as
`_orig` / `_sopt` pairs against a plain composite, plus a pixel-shader separable
reference). The batch file times them on D3D11, D3D12 and Vulkan at 1080p and 4K.

## How to time

1. One game/scene, fixed camera, same resolution for all runs (note it).
   Turn off every other effect.
2. Enable exactly one `TOPT_` technique at a time and read its GPU time in
   ReShade's Statistics tab. Let it settle ~10 s and note a typical value.
3. Fill in `timings_template.csv` (one row per technique, µs).
4. Optional: `#define TOPT_FORMAT R11G11B10F` (or `RGBA16F`) in the preprocessor
   settings and repeat a few rows to compare formats (expected: RGB10A2 =
   R11G11B10F, RGBA16F slower on bandwidth-bound passes).
5. `TOPT_Blur.fx`: one row per `TOPT_BLUR_SIZE` in the template (sizes on
   both sides of each size-class change; the notes column has the model's
   estimate; "tune" = the Size fine-tune slider). Performance mode on, except
   the "live uniforms" rows.
6. If the timings are too noisy, regenerate with `--repeat 10`: every
   technique then runs its passes 10x, and you divide by 10.

## What each micro test tells us

* `TOPT_M_Composite`: the plain composite pass (the floor every blur pays).
* `TOPT_M_TapsNN`: one full-res pass with NN bilinear taps + composite.
  Flat for small NN means memory-bound (the model says flat up to ~6 taps),
  the slope afterwards is the texture-fetch rate.
* `TOPT_M_ChainNN`: NN tiny 1/64-res passes + composite. The slope between
  Chain01, Chain08 and Chain32 is the fixed per-pass overhead (model: 5 µs).
* `TOPT_M_Down*`: the first downsample pass alone (x2 with 1 tap, x4 with 4, 9
  or 16 taps, x8 with 16). The model says all of these cost about the same
  (one full-res read).
